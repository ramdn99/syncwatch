# SyncWatch: guide for Claude Code

P2P watch-together desktop app for Windows x64 (Rust + Tauri 2 + bundled libmpv). GPL-3.0, private repo.
This is a rebuild. The binding spec is the user's project brief (sections 0-15, listed below). Decisions in spec
section 1 are final: do not re-open or re-ask them. Significant decisions go in `docs/adr/NNNN-*.md`.

## SECRETS RULE (highest priority)
- The user's Metered dev credentials live ONLY in git-ignored `.env.local` (METERED_APP, METERED_API_KEY) and
  `.env.ice.local` (ICE servers array). Never read them into output, never print, commit, log or screenshot them,
  and never put them in code, docs, fixtures, test output or the installer.
- Everywhere else use placeholders: `<USERNAME>`, `<CREDENTIAL>`, `<API_KEY>`, `<app-name>`.
- The Metered app name is part of a hostname (`<app-name>.metered.live`), so it is a secret too.
- Third-party crates are capped at `warn` level, and logs go through a scrubbing writer.
- Before every commit and every push: `pwsh -NoProfile -File scripts/secret-scan.ps1 -Mode Staged` / `-Mode History`
  (the hooks in `scripts/git-hooks` do this; enable with `git config core.hooksPath scripts/git-hooks`).
- Never capture the full screen. Capture only the app window by HWND, and only when the user says they are away.
- Never push. The user pushes manually; remind them after each milestone.
- The test video (`D:\media\test.mkv`) and other media never go in the repo. Never modify `D:\media\test.mkv`.

## Architecture
```
crates/protocol        versioned postcard protocol enum, no I/O (M2)
crates/sync-core       pure deterministic state machine (Event, Clock) -> Vec<Effect>; SimClock, FakeNet (M2)
crates/ice-config      Metered fetch/parse/validate, STUN/TURN connection test (M3)
crates/net             PeerTransport trait, bridge IPC framing (binary, batched), SDP fingerprints, watchdog,
                       signaling client (rustls+ring). NO webrtc-rs (it has no TURN over TCP/TLS) (M4).
                       The bridge itself (hidden WebView2 window) is apps/desktop/src-tauri/src/bridge.rs
                       + apps/desktop/src/bridge/bridge.ts (WebRTC plumbing only, no timers)
crates/player          Player trait; libmpv implementation (libmpv2 crate) and a mock (M1)
crates/torrent         pure PiecePolicy + in-process librqbit adapter (M7)
crates/signaling-server axum WebSocket server, :8787 /ws, /healthz (M4)
crates/syncwatch-sim   CLI with N virtual peers (M2)
apps/desktop           Tauri 2 app: src-tauri (Rust) + React/TS/Tailwind UI (M1)
assets/branding        icon.svg (NEVER edit) + generated outputs
third_party            pins.json (URLs + SHA-256), cache/ (git-ignored downloads)
scripts                check-dev-env, fetch-third-party, verify-imports, build-release, secret-scan, dev/*
docs                   adr/, build-guide.md, libmpv-build.md, checklists
```
Video: mpv renders into its OWN borderless top-level window that sits directly under the transparent main
(WebView2) window. Ownership is inverted (mpv window owns the main window) because Win32 keeps owned windows above
their owner; the fallback is manual z-order sync. See ADR 0001. All timing logic lives in Rust, never in the bridge JS.

## Build commands (pwsh 7, one per line)
```
pwsh -NoProfile -File scripts/check-dev-env.ps1 -Milestone 1
pwsh -NoProfile -File scripts/fetch-third-party.ps1
pnpm install
pnpm brand
cargo build --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
cargo test --workspace
pnpm --dir apps/desktop tauri dev
cargo run --release -p syncwatch-sim -- --seed 7
cargo run --release -p syncwatch-sim -- --latency-ms 150 --jitter-ms 60 --loss 0.2
cargo run -p syncwatch-ice-config --example live_probe   (real Metered account; prints OK/FAIL + latency only)
cargo run -p syncwatch-signaling
pwsh -NoProfile -File scripts/dev/net-lab.ps1 -Ice none -Seconds 25 -MB 64 -Release   (two instances, no input simulation)
docker compose -f deploy/compose.dev.yml up -d --build   (signaling + local coturn; always down afterwards)
pwsh -NoProfile -File scripts/verify-imports.ps1
pwsh -NoProfile -File scripts/secret-scan.ps1 -Mode All
```
`scripts/build-release.ps1` (M9) is the only supported release build path.

## Testing notes
- Run tests in the default (debug) profile: overflow checks caught a real bug that release
  builds hid. sync-core integration tests use the deterministic `sim` World (FakeNet, SimPlayer).
- Wire-format or sync changes need a test in `crates/sync-core/tests` (sync, tracks, chat, media).
- Connection tests use the in-process fake TURN server (`crates/ice-config/tests`); live Metered runs
  only via `live_probe` or `net-lab.ps1 -Ice metered`, kept rare and short, output secret-scanned before showing it.
  TLS = rustls + ring (ADR 0004).
- Network behaviour (connect time, throughput, watchdog, minimized gaps) is measured with `scripts/dev/net-lab.ps1`;
  numbers and design live in ADR 0005. Prefer `-Ice coturn` (local, free) over `-Ice metered`.
- All webviews must use the same `additionalBrowserArgs` (WebView2 shares one browser process); a test checks
  `bridge::BROWSER_ARGS` against tauri.conf.json.

## Conventions
- Static MSVC CRT (`+crt-static`, `.cargo/config.toml`). rustls only: `cargo tree -i openssl` and
  `cargo tree -i native-tls` must stay empty.
- No `unwrap`/`expect` on network or file input; user-facing errors are friendly, with "Copy diagnostics".
- libmpv and the Vulkan loader load by ABSOLUTE path with safe DLL search flags; never shell out to any binary.
- Dark theme only: no light theme, toggle or prefers-color-scheme. Tokens live in `apps/desktop/src/theme`.
- All Metered help and error text lives in `apps/desktop/src/strings/connection-help.ts`; unverified lines are
  marked `TODO-VERIFY`.
- Check crate and API versions against official docs or source before use. Pin third-party downloads by SHA-256.
- Scripts target PowerShell 7 (`pwsh`), are idempotent, and must not leave servers running.
- Docs give shell commands one per line.
- Commits end with the Co-Authored-By trailer. Run the secret scan first.

## Milestone protocol
After each milestone: build, clippy -D warnings, rustfmt, tests green, secret scan, commit; then stop with a summary,
verification steps for the user, a works/not-yet table, what to install for the next milestone, and a
`git push` reminder. Tell the user what to install only at the start of the milestone that needs it.
